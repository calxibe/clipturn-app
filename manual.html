Start here

What ClipTurn does

ClipTurn physically turns the picture stored in a video by 90° left, 90° right, or 180°. It does not merely add an orientation hint that another player may ignore.

↻

The pixels are turned

The saved result carries the new orientation with it to players, editors, websites, and other devices.

✓

The candidate is checked

ClipTurn verifies the complete candidate before using it to replace the selected source file.

≋

Important content is preserved

It preserves compatible audio, timing, metadata, tracks, colour information, and container details—or refuses.

!

A refusal is a result

If ClipTurn cannot prove a faithful replacement, it explains the limitation and leaves the source unchanged.

Know this before your first rotation.

A successful rotation replaces the selected video in place. File Explorer rotations never keep a persistent backup and cannot be undone in ClipTurn. In-app backups are optional and off by default. Keep an independent copy of irreplaceable media.

Compressed video is re-encoded.

Under the recommended policy, compressed video is decoded, turned, and encoded again with a quality-preserving target. That is not mathematically lossless, and repeated saved rotations can accumulate quality loss. Supported uncompressed AVI is the only sample-exact path.

Setup

Install and first launch

  1. Install ClipTurn from Microsoft Store

    Open the ClipTurn Store page, select Get or Install, and let Windows finish the installation. ClipTurn is currently free and self-contained; there is no separate .NET runtime to install.

  2. Open ClipTurn once

    Launch it from Start or Microsoft Store. The main window opens on Rotate Video.

  3. Check your preferred defaults

    Open Settings. The recommended defaults are suitable for most people: Keep codec and quality, preserve modification time, one concurrent job, and no persistent backup.

  4. Try a replaceable test video

    Before processing valuable media, rotate a short copy and inspect it in the player or editor you normally use.

Language

Language defaults to Auto. ClipTurn follows Windows when it is set to English, Simplified Chinese, Spanish, German, French, Japanese, Portuguese (Brazil), Italian, Korean, Polish, Russian, or Norwegian Bokmål, and uses English for every other language. You can choose one of the twelve languages in Settings instead. The open app changes immediately, and the choice is saved for the next launch and for result cards. File names, paths, codec names, and technical identifiers are never translated.

Drag-and-drop behavior

  • Drop exactly one file to switch to Rotate Video and open it, unless Batch Rotate is already selected.
  • While Batch Rotate is selected, dropping even one file appends it to the list.
  • Drop multiple files anywhere to switch to Batch Rotate and append files not already represented in the list.
  • A folder dropped anywhere switches to Batch Rotate and adds supported videos directly inside it; subfolders are not searched.
  • You cannot change the selected source while a rotation may still own it.

Workflow 1

Rotate from File Explorer

Use this route when the direction is already obvious and you do not need a preview or persistent backup.

  1. Select one or more videos

    The menu is available for MP4, M4V, MOV, MKV, AVI, WMV, and WebM. Every selected item must use a registered extension.

  2. Open the ClipTurn submenu

    Right-click the selection and choose ClipTurn – Video Rotator.

  3. Choose the direction

    Select Rotate video left or Rotate video right. With a multi-selection, the direction is applied independently to every selected video.

  4. Read the result card

    ClipTurn queues the request outside File Explorer, prepares and checks each file, then reports rotated, refused, failed, or uncertain outcomes.

The Explorer result card

  • It appears without stealing keyboard focus and shows progress while the worker runs.
  • A clean success closes automatically after a short countdown; interacting with the card keeps it open.
  • Mixed results or failures remain open until you close them.
  • If ClipTurn proves a separate-copy alternative for an unchanged source, select the blue Review options button to open the same explicit review used inside the app. Copy details and Close remain neutral so the next step is unambiguous. A one-file Explorer request opens Rotate Video; every multi-file request opens Batch Rotate with only its reviewable files, even when just one is eligible.
  • Select Copy details, or press Ctrl+C, to copy the complete report.
  • Use Tab or Shift+Tab to reach a card button and Enter or Space to activate it. Use the mouse wheel or Up, Down, Page Up, Page Down, Home, and End to read a long report. Esc closes it.
Explorer rotations have no undo copy.

The app’s backup setting does not apply to the automatic preserve-and-replace request. A successful Explorer rotation replaces the source after verification and removes its temporary rollback material. If that safe replacement is impossible, Review options can open a separately named copy choice in the app; the original remains unchanged and the copy does not start without approval. To preview first or keep a replacement backup, use Open in ClipTurn instead. That command loads the selected file on Rotate Video; open Details there when you want the full inspection window.

Do not submit an uncertain request again.

If the card says ClipTurn could not confirm a terminal outcome, check Recent Jobs and inspect the video first. It may already carry the turn; sending the same request again could rotate it to 180°.

Workflow 2

Rotate one video in the app

  1. Open the source

    Select Locate file or Locate a video, then choose one supported file. You can also drop one supported video anywhere outside an already selected Batch Rotate tab; ClipTurn switches to Rotate Video automatically.

  2. Check the video

    Select Play to preview playback. Select the filename or Details to inspect streams, geometry, file properties, and any existing ClipTurn receipt.

  3. Set the direction

    Every click on Rotate left or Rotate right adds another 90°. The Current value cycles through 0°, 90°, 180°, and 270°. Select Reset to return to 0°.

  4. Save once

    Select Save rotation. ClipTurn stores the current settings with the request, releases the preview’s file handle, and starts the worker. For a 180° turn, click twice and save once rather than completing two separate 90° saves.

  5. Read the durable result

    The result explains whether the file was rotated, safely refused, failed while unchanged, or needs inspection. The same request is also available in Recent Jobs.

The preview is non-destructive.

Left, right, and reset controls only change what you see until you select Save rotation. Closing the app or choosing another file before saving does not modify the source.

“Stop waiting” does not stop the rotation.

It detaches the foreground window so you can stop watching. The worker continues safely, and its result appears in Recent Jobs. File and source controls remain unavailable until ClipTurn proves that the worker has released the file and any required recovery has finished.

Inspect before and after

Preview, playback, and Video Details

Preview answers “is this the direction I want?” Details answers “what is in this file?” Neither is a promise that the complete rotation path will succeed; the real save performs deeper codec, stream, replacement, and verification checks.

Preview playback

Playback does not start automatically. Use Play and Pause; the preview does not loop.

If preview playback fails, ClipTurn can still let you request rotation because preview and processing use different checks.

File access

Select the filename or Details button to open the one Details window. A second selection brings the same window forward and refreshes it.

Right-click the filename, or use the context-menu key, for Copy full path.

Workflow 3

Batch Rotate

Batch Rotate applies one selected direction to a list. Every row is still its own job, so a refusal or a reviewed-copy choice does not hide or stop the others.

  1. Choose one direction

    Select Rotate left 90°, Rotate right 90°, or Rotate 180°. The initial selection is right 90°. The selected direction applies to every eligible row started in that run.

  2. Add files

    Select Add videos for a multi-file picker, drop one or more files while Batch Rotate is selected, or drop multiple files or a folder anywhere in ClipTurn. The app switches to Batch Rotate when needed and skips files already represented in the list. You can stop a slow folder read with Stop adding; rows already read remain in the list.

  3. Review the list

    Each row shows the filename and folder, Length, displayed Resolution, Size, Status, and a selectable reason when relevant. Long filenames and folder paths end in an ellipsis; point to either line to see its complete value. A dash means metadata could not be read; it is not itself a rotation verdict.

  4. Remove what you do not want

    Use Remove selected or Clear list before starting. Rows committed to an active run cannot be removed.

  5. Start the work

    Select Rotate the list. ClipTurn snapshots the eligible rows, chosen direction, and current settings. Maximum concurrent jobs controls how many workers can run at once.

  6. Read every result

    One file may rotate while another safely refuses or stops at Review available. The status and complete reason stay with each row, and the durable record is also written to Recent Jobs.

Review conversions before creating separate copies

Preserve-and-replace is always tried first. If the exact source cannot be replaced faithfully but this PC proves it can start a separate-copy route, the row stops at Review available. Select Review conversions to see the recommended strategy and every relevant change before anything else starts.

  • A lossless MP4, M4V, or MOV display copy changes only the orientation instruction; some older players and editors may ignore it.
  • An eligible SDR compatibility copy physically rotates the picture into H.264 MP4 and lists its wider codec, track, metadata, and timing boundary.
  • Approved outputs are verified, saved beside their sources under new names, and never replace the originals.
  • Changing the source after review invalidates the old approval; ClipTurn checks the exact reviewed fingerprint again before processing.

What happens when you add a folder

  • Only supported files directly inside that folder are added.
  • Subfolders are never searched recursively.
  • Unsupported files found inside a folder are counted and skipped instead of filling the list.
  • An explicitly selected unsupported file can remain as a Cannot rotate row with its reason.
  • The same physical file cannot be added twice through another spelling, hard link, junction, subst drive, or short path.
Stopping a batch is deliberately graceful.

Stop after the current videos prevents new rows from starting. Workers already processing files finish. Untouched waiting rows return to Not started; select Rotate the list later to run exactly the remainder.

Durable history

Recent Jobs

Recent Jobs is the first place to look after closing a progress window, selecting Stop waiting, recovering from an interruption, or seeing an uncertain batch status. It reads the request and result records that the worker saved locally—not a temporary message from the main window.

When it updates

  • The list loads when you select the Recent Jobs tab.
  • It refreshes every five seconds while that tab remains visible.
  • It refreshes when an in-app rotation completes.
  • Select Refresh whenever you want an immediate reread.

What each card contains

  • The requested direction, overall status, local time, and job ID.
  • Up to ten per-file outcomes for a completed request.
  • The full path, whether the source was replaced, stayed unchanged, or may have changed, and the worker’s exact message.
  • A Review options action when the validated result still has one or more separate-copy choices, including results first shown by File Explorer.
  • For a request still awaiting a result, up to five queued paths so you can identify the work.
The page shows the ten newest jobs.

Older job records can remain in ClipTurn’s local data folder even though the interface shows only ten. There is no Clear history button in version 1.0.5. Uninstalling the app removes its packaged local data; rotated files and backups remain where you saved them.

Exact-file evidence

Verification receipts

A receipt records what ClipTurn proved about one exact on-disk version of a video. It is local evidence, not a permanent badge embedded in the media.

Fast lookup versus full recheck

When Details opens

ClipTurn compares file identity, byte length, and last-write time with its receipt index. This is fast and does not read or hash the video payload.

Verify file again

ClipTurn reads the complete current file, calculates SHA-256, and compares that fingerprint with the receipt. A large file can take time; use Cancel verification to stop only this recheck.

Receipts do not travel inside the video.

They are stored under ClipTurn’s package LocalState, not as a sidecar file, alternate data stream, or embedded tag. Copying the video to another PC does not copy its receipt. Editing or replacing the file makes an older receipt stale even if the filename stays the same.

Reference

Settings

Rotation settings apply to jobs started in the app and File Explorer, except for the backup switch. Explorer always requests no persistent backup. Every setting saves as soon as you change it, and an in-app rotation captures the values currently shown. There is no separate Save settings step.

SettingDefaultEffect
Default policy Keep codec and quality Controls whether compressed, visually lossless re-encoding is allowed or sample-exact output is required.
Create a backup before replacement Off For rotations started inside the app only, keeps the original beside the source as name.backup-XXXXXXXX.ext.
Preserve the original modification time On Restores the source file’s last-modified timestamp after a verified replacement.
Keep failed temporary files for diagnostics Off Retains failed candidate files under LocalState’s Working folder. These can be large and are for investigation, not normal playback.
Maximum concurrent jobs 1 Allows 1–32 independent worker jobs at once. Higher values use more CPU, hardware codec sessions, storage bandwidth, memory, and temporary space.
Appearance Auto Auto follows Windows. Light and Dark force that app appearance. Windows high-contrast colors remain supported.
Language Auto Auto follows a supported Windows language and otherwise uses English. Choosing a language updates the open app immediately and saves the choice.

A sensible concurrency choice

  • Leave it at 1 for the most conservative disk and codec usage.
  • Increase gradually for many independent short videos on a capable PC and fast local storage.
  • Reduce it if hardware encoders refuse parallel sessions, the PC becomes unresponsive, or temporary storage fills quickly.
  • Concurrency does not weaken per-file verification; it only changes how many independent files are active.

Diagnostics

The Diagnostics card shows the exact local data path. Select Open ClipTurn data folder to inspect settings, requests, results, recovery records, working candidates, and receipts. Do not edit or delete active-job files while a worker may still be running.

Quality and exactness

Choose a processing policy

PolicyFidelity requirementSize rulePractical coverage in 1.0.5
Keep codec and quality Recommended Allows a quality-preserving re-encode for compressed picture; tries to keep the source codec and names an eligible fallback. No output-size ceiling. Quality is not lowered merely to match source bytes. Compressed supported paths plus sample-exact AVI.
Strict Requires a sample-exact pixel permutation. Output may not exceed the source by more than the container tolerance: the larger of 64 KiB or 1%. Eligible uncompressed packed-pixel AVI only.
Exact Requires the same sample-exact pixel permutation. No size ceiling. Eligible uncompressed packed-pixel AVI only.

Keep codec and quality in plain language

ClipTurn targets the source picture bitrate and normally writes the turned picture in the source codec—for example H.264 as H.264, VP9 as VP9, and WMV as the matching Windows Media subtype. Where an explicitly supported fallback is necessary, the result names it; an eligible 8-bit HEVC source can, for example, fall back to H.264 when no usable HEVC encoder exists. A 10-bit HEVC source never silently falls back to 8-bit.

Strict and Exact are not higher-quality modes for compressed phone videos.

They demand mathematical sample-level proof that a decode/encode cycle cannot provide. A normal MP4, MOV, MKV, WebM, or WMV therefore refuses under these policies. Choose the recommended policy only when you accept one quality-preserving re-encode of the picture.

Changing policy does not remove fundamental limits.

Missing codecs, unpreservable subtitles, multiple video tracks, unsupported colour geometry, read-only files, unsafe storage, and other fidelity gates still refuse. Exact policies never silently fall back.

Behind every save

How replacement stays safe

ClipTurn treats rotation as a verified file-replacement transaction. It does not overwrite the source incrementally while frames are still being produced.

  1. Admit the source.ClipTurn validates the path, extension, storage type, attributes, file identity, and request.
  2. Snapshot it.The worker records source properties and a complete SHA-256 fingerprint while holding the required file access.
  3. Build a separate candidate.The turned output is produced away from the source. The original is not used as an in-place encoding target.
  4. Verify the candidate.ClipTurn decodes the complete video, checks the physical turn, checks the complete audio path, and compares the container, tracks, and supported metadata it promised to preserve.
  5. Recheck the source.Before commit, ClipTurn confirms that the selected source is still the exact file version it inspected and that no competing request owns it.
  6. Stage and replace.A flushed same-volume staged copy is committed with Windows’ replacement operation and internal rollback material.
  7. Record the outcome.The durable result, journal state, and exact-file receipt are saved after the installed result is known.

Storage and file gates

Protection against two turns

Requests for the same physical file are compared across paths and processes. When overlapping requests arrive, the oldest eligible request owns the turn and later requests receive a durable, non-modifying refusal. This includes path aliases and hard links that resolve to the same NTFS file identity.

External changes are preserved, not guessed through.

If another program changes or replaces the source after ClipTurn inspected it, ClipTurn can report Source changed or an unknown outcome instead of overwriting unfamiliar bytes. Inspect the on-disk video and Recent Jobs before deciding what to do next.

When something interrupts the work

Backups, interruption, and recovery

Persistent backups

In-app rotation

Turn on Create a backup before replacement before starting. On success, the original remains beside the source with a name such as holiday.backup-a1b2c3d4.mp4. ClipTurn does not delete that requested backup later.

File Explorer rotation

Never keeps a persistent success backup, regardless of the app setting. Use Open in ClipTurn when a backup is required, or make an independent copy first.

Internal rollback is not an undo feature

Every replacement can use hidden, same-volume rollback and staging files while the transaction is active. These exist so recovery can determine which bytes belong at the source path after an interruption. They are normally removed after a durable success and are not a persistent copy you can restore through the UI.

Interruption pointRecovery behavior
Before replacementThe original source remains in place; recovery removes only artifacts it can identify safely.
After replacement, before final bookkeepingThe journal can recognize the already-installed candidate, finish the durable result, and avoid applying the turn again.
Source missing with a proven rollbackRecovery can restore the known original.
Unexpected or newer external contentClipTurn preserves it and reports that the source changed instead of overwriting it.
Receipt publication interruptedA replay can publish the missing receipt from the durable result without rotating again.

Safe stop controls

  • Stop waiting ends only the main window’s wait; the worker continues.
  • Stop after the current videos ends batch dispatch only; active workers continue.
  • Stop adding ends a folder/file-list read; already admitted rows remain.
  • Cancel verification ends a manual SHA-256 recheck; it does not affect a rotation worker.
Do not blindly delete recovery artifacts or resend the turn.

A rare cleanup problem can leave a hidden name containing .cliptc.rollback or .cliptc.tmp beside the source, with the exact path named in the result. First read Recent Jobs and inspect the source. If the state is still unclear, copy the result and contact support.

The app picker, drag-and-drop, and batch folder scan can accept them and offer a reviewed, physically rotated H.264 MP4 copy when this PC proves the required decode and encode paths. The MPEG source stays unchanged. Raw elementary streams such as .m2v/.mpv and DVD objects such as .vob retain their refusal boundaries.

Deep format reference

Container-specific behavior

MP4, M4V, and MOV
  • H.264 is physically rotated and written as H.264 High profile when the full path verifies.
  • Eligible 8-bit HEVC stays HEVC when a usable encoder exists. If none does, a permitted H.264 fallback is named clearly in the result.
  • Eligible HEVC Main10 can stay 10-bit P010/Main10 with supported BT.2020/PQ and declared HDR10 static metadata only when a Main10 encoder accepts it. It never falls back to 8-bit.
  • The writer preserves supported capture/media-created time, camera/GPS/time-zone metadata, audio language, colour declarations, display geometry, and the compatible major container brand, then verifies the promised result.
  • If faithful replacement is refused, a reviewed H.264 compatibility copy keeps MP4/M4V/MOV movie times, complete movie-level identity metadata—including GPS and camera details—and retained track languages. An independent reader compares the exact values and bytes before publication; failure leaves the source unchanged and publishes no copy.
  • That compatibility copy deliberately remains a standard MP4 instead of inheriting a MOV/M4V brand. Extra soundtrack, subtitle, chapter, timecode, per-frame sensor and other auxiliary tracks can still be omitted as listed in the approval dialog; metadata from non-MP4 source containers is not yet mapped into the new MP4.
  • Ordinary iPhone timecode or sensor metadata tracks may be dropped with an explicit note. A Live Photo MOV is refused so the separately paired still image is not broken.
  • Fragmented files, a second video or audio track, subtitles, chapters, unknown tracks, non-square or fractional display geometry, field-coded/interlaced H.264, HLG transfer 18, sRGB transfer 13, and certain rewritten colour matrices refuse.
  • Dolby Vision enhancement metadata cannot survive this path. When an eligible base HDR layer can be preserved, the result names the dropped enhancement metadata.
MKV
  • Supported H.264/HEVC and VP8/VP9 picture paths re-encode the turned picture while attempting to preserve the picture codec.
  • Every admitted audio track is copied as compressed packets and verified by counts, bytes, and payload hashes. If exact copy cannot be proven, the file refuses.
  • Multiple audio tracks, SubRip/UTF-8 text, Matroska WebVTT text, track language/name/default/forced flags, attachments, tags, IDs, date, title, and supported display/colour data can be carried within verified limits.
  • Chapters, a second video track, PGS/VobSub/DVB/BMP bitmap subtitles, ASS/SSA and other styled scripts, unknown subtitle types, or content encodings ClipTurn cannot preserve are refused rather than stripped.
  • 10-bit HDR MKV is refused in version 1.0.5 because the output path cannot preserve the required declarations faithfully.
WebM
  • VP8 remains VP8 and VP9 remains VP9, for supported 8-bit 4:2:0 sources. Every saved turn creates a new compressed picture generation.
  • Audio must be Opus or Vorbis and is copied packet-exactly. Supported WebVTT subtitle variants can be carried.
  • The free Microsoft VP9 Video Extensions package is required for planning both VP9 and VP8/WebM paths. ClipTurn’s bundled VP8 encoder does not replace the Windows decoder requirement.
  • AV1, VP9 Profile 2 10/12-bit, Profile 1/wider chroma, alpha/block additions, other audio, chapters, attachments, non-WebVTT subtitles, and a second video refuse.
  • If every track starts before zero, ClipTurn can shift the shared timeline to zero without changing synchronization. Missing default frame duration can be derived from individual frame timing.
WMV
  • Eligible Windows Media Video 7, 8, 9, and VC-1 picture is re-encoded to the matching subtype.
  • Admitted WMA or MP3 audio is copied as original packets and verified rather than re-encoded.
  • Supported Title, Author, Copyright, Description, numeric/Boolean/blob extended metadata, and pixel-aspect data can be preserved.
  • WMV screen codecs MSS1/MSS2, deprecated VC-1 variants, Microsoft MPEG-4 variants, H.264/HEVC/VP9/AV1 inside ASF, DRM, multi-bitrate structures, scripts, markers, branding, and unpreservable audio refuse.
Uncompressed AVI
  • Supported stored pixels are 24/32-bit RGB, 16-bit RGB, 8-bit indexed colour, and 8-bit grayscale in the admitted uncompressed layout.
  • ClipTurn permutes stored pixels directly and independently compares the full result. Admitted audio is copied byte-for-byte.
  • A quarter turn swaps width and height. For 24-bit video with odd dimensions, AVI row padding can make the result slightly larger even though every pixel is exact.
  • Strict accepts only its small container-overhead tolerance; Exact allows a larger exact file. The projected AVI 1.0 result must remain below 2 GiB.
  • YUY2, UYVY, NV12, I420/IYUV/YV12 and other chroma-subsampled raw layouts refuse because a quarter turn would require resampling chroma.
  • MJPEG, DivX/Xvid and other MPEG-4 Part 2, DV, Cinepak, Microsoft Video/RLE, WMV, H.264/HEVC in AVI, and other compressed or professional/lossless AVI codecs refuse.

Beyond the picture

Audio, subtitles, tracks, and metadata

Audio is exact copy or refusal

ClipTurn does not hide an incompatible soundtrack behind a lossy AAC conversion. For an admitted path, it copies original compressed packets or bytes and verifies the complete soundtrack; if that exact route cannot be proved, the file is refused unchanged. This rule applies differently by container:

  • MP4 family: at most one audio track, which must pass a disposable write/reopen and complete packet-passthrough proof.
  • MKV: all admitted audio tracks are copied packet-exactly; unusual codecs still refuse if their exact file cannot be proved.
  • WebM: Opus or Vorbis only, copied exactly.
  • WMV: only audio that the ASF output can preserve as original packets.
  • Uncompressed AVI: an admitted audio stream is copied byte-for-byte.

What “preserve metadata” means

Preservation is format-specific, not a blanket promise. ClipTurn compares the source with the candidate for the properties its route knows how to carry—such as timing, language, display geometry, colour/HDR declarations, capture dates, camera/GPS fields, tags, IDs, attachments, or ASF attributes. If a required property would be rewritten or dropped outside an explicitly disclosed exception, the file is refused.

Use it your way

Accessibility and keyboard use

  • Use standard Windows keyboard navigation: Tab and Shift+Tab move between controls; Enter or Space activates the focused button or link.
  • The selected filename is a real keyboard-accessible link. Use Enter or Space for Details, or the context-menu key/right-click for Copy full path.
  • Progress and important status text use screen-reader live announcements without moving focus unexpectedly.
  • Buttons include automation names or help text where the visible label alone would not explain the consequence—especially Stop waiting and batch stop.
  • Batch rows announce the filename and status together, and selection colors include explicit Windows high-contrast resources.
  • Appearance can follow Windows automatically or be forced to Light or Dark. Auto follows the system light/dark choice and remains compatible with Windows high contrast.

Explorer result-card keyboard controls

Find the symptom

Troubleshooting

Which versions of Windows does ClipTurn support?

ClipTurn supports Windows 11 and Windows 10 version 2004 (build 19041) or later. On Windows 10, the PC must use the 64-bit (x64) version of Windows; 32-bit Windows is not supported.

On Windows 11, ClipTurn supports both standard x64 PCs and ARM64 PCs. Microsoft Store selects the compatible package automatically.

The ClipTurn menu is missing in File Explorer

Confirm that the selection contains only files ending in .mp4, .m4v, .mov, .mkv, .avi, .wmv, or .webm. The menu stays hidden when any selected item is unsupported.

MPEG/VOB extensions are intentionally not registered. If supported files never show the menu, confirm the Store installation completed and restart File Explorer or sign out and in before contacting support.

The video plays or previews, but rotation is refused

Playback proves only that a decoder can display the source. ClipTurn also needs an eligible encoder, container writer, exact audio route, supported track/geometry/colour layout, safe file location, and a candidate that passes complete verification.

Read the per-file result, then open System Capabilities only when the message names a missing codec path.

Strict or Exact refuses an ordinary phone video

This is expected. Compressed video cannot be rotated sample-exactly through decode and encode. Strict and Exact currently cover eligible uncompressed AVI only.

Select Keep codec and quality if you accept a quality-preserving re-encode, then save the setting and try once more.

A WebM or VP8/VP9 file refuses on a normal Windows installation

Install Microsoft’s free VP9 Video Extensions using the exact action ClipTurn provides, then restart affected apps and select Analyze this PC again. VP8 planning also depends on this Windows package.

The file can still refuse for 10-bit/profile, alpha, audio, subtitle, chapter, attachment, or multi-video limits.

HEVC or Main10 is unavailable

For 8-bit HEVC, use the official HEVC extension link offered by ClipTurn when present. It may be a separately priced Microsoft Store product. Eligible 8-bit input can use a clearly named H.264 fallback when no HEVC encoder is usable.

Main10 encoding normally depends on hardware and a matching driver. Install the exact manufacturer driver for the PC/GPU, restart, and analyze again, or use another capable PC. ClipTurn does not silently convert 10-bit to 8-bit.

Media Foundation is unavailable on Windows N

Open Windows Settings → System → Optional features, add Microsoft’s free Media Feature Pack, restart Windows, and run System Capabilities again.

A cloud, network, removable, or read-only file is refused

Make a cloud file fully available on this device, ensure it is writable, and place it on a local fixed NTFS volume. A hydrated OneDrive file on local NTFS can be eligible, but the sync client may upload the changed result afterward.

ClipTurn intentionally refuses storage where its same-volume replacement, identity, and recovery guarantees cannot be proved.

The rotated file is larger than the original

This can be normal under Keep codec and quality. ClipTurn targets the source quality/bitrate and has no compressed-output size ceiling; it does not spend picture quality simply to hit the old byte count.

Strict has a small container-overhead tolerance, but applies only to exact AVI. Exact allows exact AVI to grow without that ceiling.

The app looks stuck on Preparing or processing

Large files, full-stream verification, slow storage, codec startup, or recovery can take time. Select Stop waiting when offered to release the foreground wait; the rotation continues safely.

Check Recent Jobs later. Do not kill and resubmit the same file while the outcome is uncertain.

I stopped a batch, but some videos are still running

Stop after the current videos is working as designed. It stops dispatching new rows but does not terminate workers that already own files. Those rows finish; untouched rows return to Not started.

Select Rotate the list later to process the remainder.

A verification receipt says the file changed

The current identity, length, modified time, or full SHA-256 no longer matches the recorded version. Rename/move behavior depends on available file identity, but any content edit or replacement makes the old proof stale.

Verify file again hashes the current bytes; it does not restore an older receipt or undo an edit.

An AVI refuses because it would reach 2 GiB

ClipTurn writes the supported AVI 1.0 layout and refuses a projected output at or above 2 GiB. A 90° turn can change row padding and therefore size even when every stored pixel is exact.

The result mentions a subtitle, chapter, attachment, or extra track

ClipTurn will not silently delete or reposition a structure it cannot preserve and verify. Changing processing policy does not make that layout safe. Keep the source unchanged or deliberately remux/convert a copy in a tool suited to that task.

A row says Outcome unknown or Source changed

Do not retry. Open Recent Jobs, inspect the physical video, and determine its current orientation first. A second turn could produce an unintended 180° result.

If you still cannot establish the state, copy the result and contact support before deleting any recovery material.

Plain language

Glossary and quick reference

Source
The selected video at its original path—the file ClipTurn intends to replace only after verification.
Candidate
The separate turned file ClipTurn builds and verifies before replacement.
Physical rotation
Turning stored picture samples so orientation does not depend on a display flag.
Container
The file structure identified by extensions such as MP4, MKV, WebM, WMV, or AVI; it holds video, audio, timing, and metadata.
Codec
The method used to encode picture or sound inside the container, such as H.264, HEVC, VP9, or WMA.
Re-encode
Decode compressed picture, turn it, and encode it again. The recommended policy aims to preserve perceived quality but cannot be sample-exact.
Sample-exact
The stored pixel samples are permuted without a lossy codec generation and independently compared. ClipTurn provides this only for eligible uncompressed AVI.
Packet passthrough
Copying encoded audio packets without decoding or re-encoding them, then proving the complete payload was carried.
Receipt
A local record tied to one exact file version, containing the outcome, fingerprint, and only the verification facts ClipTurn established.
Safely refused
No eligible route existed, and ClipTurn proved the source remained unchanged.
Outcome unknown
ClipTurn cannot prove whether the source changed; inspect before any retry.

One-screen reminder

Preview first: Open in ClipTurn → choose direction → Save rotation.

Turn 180°: select two 90° preview turns → save once.

Keep original: Settings → turn on Create a backup → rotate inside the app.

Many files: Batch Rotate → choose direction → add → review → Rotate the list.

Uncertain result: do not retry → Recent Jobs → inspect video → copy report if needed.

Missing codec: System Capabilities → exact official action → restart if requested → Analyze again.
