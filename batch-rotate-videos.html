How to batch rotate multiple videos at once

A phone held the same way all afternoon produces a folder of clips that all need the same quarter turn. Doing that one file at a time in a video editor is an evening's work. This is how to do the whole folder in one run on Windows — and, more importantly, how to keep a separate answer for every file so one awkward clip does not take the rest down with it.

Pick a route

Two routes, and when each wins

Windows has no built-in way to rotate even one video, let alone forty. Both routes below come from installing a rotation app; the difference is how much control you want before anything starts.

Route Best for What you give up
Multi-select in File Explorer A handful of clips you already know need the same turn. Select, right-click, choose a direction, done. No list to review first, and no persistent backup — Explorer rotations never keep one.
Batch Rotate More control A whole folder, a mixed set, or anything you want to inspect before committing. Every file appears as a row with its own length, resolution, size and status. A few more clicks, and the app has to be open.
Batch work is where an irreversible mistake gets multiplied.

A successful rotation replaces the original file. One wrong direction on one clip is an annoyance; the same mistake across ninety clips is an afternoon of re-rotating and two encode generations on every one of them. Copy anything irreplaceable first, and try the direction on a single file before you commit the folder.

Route 1

A handful of clips, from File Explorer

  1. Select the videos

    Click the first, then Ctrl-click the others, or Ctrl+A for everything in the folder. Every item in the selection must be a supported type — .mp4, .m4v, .mov, .mkv, .avi, .wmv or .webm. If any file is something else, the menu stays hidden entirely.

  2. Right-click and choose a direction

    Open ClipTurn – Video Rotator and select Rotate video left or Rotate video right. The direction is applied to each selected video independently.

  3. Read the result card

    One card reports the outcome for every file in the selection: rotated, refused, failed or uncertain. Mixed results keep the card open until you close it, so a single refusal in a batch of twenty is not something you can miss.

Explorer rotations keep no backup.

The app's backup setting does not apply to them, whatever it is set to. To keep the originals, use Open in ClipTurn instead and turn on Create a backup before replacement in Settings before you start.

Route 2

A folder, in Batch Rotate

  1. Choose one direction first

    Rotate left 90°, Rotate right 90° or Rotate 180°. The initial selection is right 90°. Whatever you pick applies to every eligible row started in that run, so it is worth setting before you add anything.

  2. Add the videos

    Use Add videos for a multi-file picker, or drop files or a whole folder onto the window. Only supported videos directly inside a dropped folder are added — subfolders are deliberately never searched, so a folder of folders adds nothing you did not expect. Files already in the list are skipped rather than duplicated.

  3. Review before you commit

    Each row shows the filename and folder, length, displayed resolution, size and status. A dash means metadata could not be read — that on its own is not a rotation verdict. Use Remove selected or Clear list to drop anything you do not want.

  4. Start the run

    Select Rotate the list. ClipTurn takes a snapshot of the eligible rows, the chosen direction and your current settings, so changing a setting mid-run does not alter work already committed.

A slow folder read can be stopped.

Reading a large folder over a slow drive can take a moment. Stop adding ends the read; rows already found stay in the list, so you can start with those and add the rest later.

The point of a batch

Reading the per-file results

This is what separates a real batch tool from a loop: every row is its own job, so one file being refused never stops, hides or corrupts the others.

Status What it means Can you run it again?
RotatedThe verified result replaced the source.No — a second turn is prevented deliberately
Rotated copy createdA separately named output passed verification; the original was untouched.No, the reviewed request is complete
Review availableExact replacement stopped safely and a separate-copy route is available for approval.Use Review conversions and approve it explicitly
Refused safelyNo faithful route existed and the source is proven unchanged.Yes, once you change the setting or capability it named
FailedThe attempt stopped before modifying the source, or the file could not be found.Yes, after fixing the cause

Never re-run an Outcome unknown row without looking.

If the turn already applied, sending it again leaves that video 180° from where it started. Open Recent Jobs, then open the video itself and establish which way up it currently is. Only then decide.

Every outcome is also written to Recent Jobs, so closing the window or restarting the app does not lose the record. The manual lists every status and retry rule.

Changing your mind

Stopping a run safely

There is no kill switch, and that is deliberate: terminating a worker mid-write is exactly how a video gets truncated.

  • Stop after the current videos prevents new rows from starting. Files already being processed finish properly.
  • Untouched waiting rows go back to Not started, so selecting Rotate the list later runs exactly the remainder.
  • Rows already committed to the active run cannot be removed from the list until they finish.
  • Closing the progress window is not the same as stopping. The work continues safely and the results appear in Recent Jobs.

Speed against safety

How many at once

Maximum concurrent jobs in Settings allows 1 to 32 workers at a time. The default is 1, which is the most conservative use of your disk and codecs.

  • Raise it gradually for many short clips on a capable PC with fast local storage.
  • Lower it if hardware encoders refuse parallel sessions, the PC becomes unresponsive, or temporary storage fills up quickly.
  • Concurrency never weakens per-file verification. It changes how many files are active, not how carefully each one is checked.
  • More workers is not always faster. Several large files competing for the same drive and the same hardware encoder can finish slower than running them one after another.

The usual complication

Clips that need different directions

One direction applies to the whole run. That is correct for a folder filmed the same way and wrong for a mixed set, so split the work:

  1. Sort the clips by eye first

    Explorer's large-icon view shows video thumbnails, which is usually enough to see which way each clip is lying without opening any of them.

  2. Run the larger group

    Add only those files, set their direction, and rotate the list.

  3. Clear the list and run the rest

    Select Clear list, add the remaining clips, choose the other direction, and go again. Already-rotated files are protected from a second accidental turn.

Upside-down clips belong in their own run.

Use Rotate 180° rather than two 90° runs. Each saved rotation is a fresh encode, so two runs cost two generations of quality where one costs one.

Worth five minutes

Before you start a large batch

  • Test on one file. Rotate a single clip from the folder and check the result in a player before committing the other eighty-nine.
  • Copy anything irreplaceable. Batch work multiplies whatever mistake you make.
  • Check free space. Each file needs room for its candidate, same-volume staging and rollback material while it is being written.
  • Move the folder off a NAS or USB stick first. Network, removable and non-NTFS storage is refused, because the guarantees needed for safe replacement are not available there.
  • Expect some refusals in a mixed folder. That is the tool working, not failing — and each refused file is left exactly as it was. The causes are listed here.

Answers

Common questions

How do I rotate multiple videos at once on Windows?

For a handful of clips filmed the same way, select them all in File Explorer, right-click, and use the rotate command once — the direction is applied to each file independently. For a folder, or for a list you want to check before starting, use ClipTurn's Batch Rotate tab, which shows every file as its own row with its own status and reason.

Can I rotate a whole folder of videos in one go?

Yes. Drop the folder anywhere on the ClipTurn window and every supported video directly inside it is added to the list. Subfolders are deliberately never searched, so a folder of folders adds nothing unexpected. Unsupported files inside the folder are counted and skipped rather than filling the list with rows you cannot use.

Can different videos be rotated in different directions in one run?

No. One direction applies to the whole run, which is what you want for a batch of clips filmed the same way and wrong for a mixed set. Rotate the clips that need one direction, then add the rest and run again with the other direction.

What happens if one video in the batch fails?

Nothing happens to the others. Every row is its own job, so a refusal, a failure or a row waiting for review does not stop or hide the rest. The status and the complete reason stay attached to that row, and a refused file is left exactly as it was.

How many videos can be rotated at the same time?

Maximum concurrent jobs in Settings allows 1 to 32 workers at once, and the default is 1. Raising it uses more CPU, hardware codec sessions, storage bandwidth, memory and temporary space. Concurrency never weakens per-file verification; it only changes how many files are active at a time.

Can I stop a batch part-way through?

Yes. Stop after the current videos prevents new rows from starting while letting files already being processed finish rather than being killed mid-write. Untouched waiting rows return to Not started, so selecting Rotate the list later runs exactly the remainder.
